## 5. 本機 DB：真正現況

- 本機開發使用 Wrangler D1 模擬器保存 SQLite，資料位於 `系統/.wrangler/state/v3/d1/` 下。
- **不得刪除 `系統/.wrangler/`**，否則主管在網頁修改的本機資料可能遺失。
- SQLite 檔名是雜湊值，可能改變；需要檢查時用 `find 系統/.wrangler -name '*.sqlite'`，不要把目前檔名寫死在程式中。
- `metadata.sqlite` 不是主要業務資料庫。
- `repository.ts` 的 `ensureDatabase()` 才是目前 runtime 建表與輕量遷移來源；Drizzle migration 不會自動取代這段流程。

## 6. 資料關係與輸入規則

- `people` 是姓名、工號等人員基本資料的唯一主檔。
- `position_people` 是多對多關係：一人可連多職位，一職位可連多位現任者及接班人。
- 職位頁新增現任者／潛在接班人時，只輸入已存在的工號，姓名由 `people` 自動帶入，不在職位頁重複維護。
- 非空工號由 `idx_people_employee_no` 保證唯一；空工號可有多筆。
- 同一人不可同時成為同一職位的「現任者」和「潛在接班人」。
- 每個職位只有一組確認狀態、確認人、確認日期、確認備註。確認流程為：待確認 → 在職人員確認 → 主管確認。
- 每個人也只有一組人員確認資訊。
